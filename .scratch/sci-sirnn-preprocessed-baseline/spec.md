## Problem Statement

当前默认 SCI+SiRNN 在初始化阶段完成 Base OT，但没有在每查询输入到来前建立随机 OT 或比较材料库存。其后续 OT 扩展、消息适配和比较材料生成发生在在线执行中。相比之下，SCI+ours 的分段 FSS 和 Beaver 材料已经在本次查询输入读入前生成，并分别报告离线成本。

这组测量能够说明显式预处理方案相对默认实现的在线延迟收益，但不能回答：如果 SCI+SiRNN 也获得输入前预处理机会，ours 还能降低多少在线延迟、通信或总成本？用户需要新增真实执行预处理的 SCI+SiRNN 基线，在 batch=128 下重新进行匹配对比。

项目已有两个容易混淆的名称：`SCI_ours` 仅替换图级截断和扩环，图级乘法及激活仍使用原生 SCI；`SCI_Beaver_segmented` 同时使用 Beaver 图级乘法和分段 FSS 转换。新报告需要分别列出这两种 ours，不能将历史组合结果当成仅转换后端的结果。

## Solution

增加 `SCI_preprocessed`，显示名为 SCI+SiRNN-preprocessed。该基线保留原生 SCI 的数值算法和图级乘法协议，在查询输入到来前真正生成输入无关的 OT 及比较材料；输入相关的选择修正、消息适配和打开保留在线执行。

将原生 SCI 预处理作为共享执行策略，使 SCI_ours 和 SCI_Beaver_segmented 的剩余原生 SCI 工作也能使用。采用相同公开计划、数值契约和资源条件，与默认 SCI 控制组一起重新测量 batch=128 单时间步。报告同时给出 setup、每查询离线、在线、直接 query total、通信和内存，分别回答默认实现对比、双方预处理后的对比，以及总成本交换。

最高层验收接口沿用现有两方 runtime 的 setup → prepare → 输入装载/ready → online → 输出/查询结束流程。正式测量关闭中间张量揭示；正确性诊断沿用默认和非零隐状态的单步整数核验。

## User Stories

1. 作为研究者，我希望增加真正预处理的 SCI+SiRNN 基线，从而判断 ours 相对具有相同预处理机会的基线是否仍有在线优势。
2. 作为基准使用者，我希望保留默认 SCI 控制组，从而区分预处理带来的收益和协议替换带来的收益。
3. 作为实验分析者，我希望分别列出 SCI_ours 和 SCI_Beaver_segmented，从而明确转换替换与乘法加转换组合的贡献。
4. 作为推理使用者，我希望在本次查询输入到来前完成随机材料生成，从而减少输入到达后的响应时间。
5. 作为协议维护者，我希望 Base OT setup 与每查询预处理分别计费，从而区分可复用初始化与一次性材料成本。
6. 作为协议实现者，我希望普通二选一 OT 使用新鲜随机 OT 及真实在线选择修正，从而避免把含真实输入的扩展通信事后改名为离线。
7. 作为协议实现者，我希望多选一 OT、批量 GOT 和线性乘法 COT 也有对应预处理路径，从而避免普通 GOT 缓存遗漏主要调用。
8. 作为协议实现者，我希望比较树使用预生成的 bit-triple，从而将输入无关材料生成与输入相关比较执行分开。
9. 作为数值验证者，我希望算术 COT 保留原有模环相关性，从而避免把 XOR 相关性误用为算术相关性。
10. 作为推理使用者，我希望 Sigmoid/TanH 内部可预处理工作也被覆盖，从而使基线收益不局限于图级外壳。
11. 作为公平性审查者，我希望 ours 剩余的原生 SCI 调用获得同样预处理能力，从而公平比较转换和乘法替换。
12. 作为运行时维护者，我希望每个协议上下文拥有自己的材料消费状态，从而兼容现有激活并行与两分支图调度。
13. 作为实验分析者，我希望材料计划只取决于公开的调用参数和调度，从而排除利用本次私有查询输入提前执行的情况。
14. 作为运行时维护者，我希望每查询生成新鲜材料并只消费一次，从而保持原有两方半诚实安全假设。
15. 作为基准维护者，我希望在线库存不足被明确记录或拒绝，从而避免预处理基线悄悄回退到在线扩展。
16. 作为部署者，我希望材料库存遵守每方内存预算，从而避免通过额外资源制造在线优势。
17. 作为性能分析者，我希望材料装载与等待按实际发生阶段计费，从而理解在线降低是否依赖大量库存读取。
18. 作为数值验证者，我希望新基线与默认 SCI 在默认和非零隐状态下逐整数一致，从而保证预处理没有改变计算结果。
19. 作为基准使用者，我希望 batch=128 的所有主表行使用相同模型、输入和共享调度，从而得到可比较的新样本。
20. 作为实验维护者，我希望每行运行十个无预热 fresh query，从而沿用已有主表的重复测量口径。
21. 作为性能分析者，我希望双方同查询最大时延的中位数和波动范围一起报告，从而避免依赖单次最快样本。
22. 作为通信分析者，我希望按双方发送字节之和分别报告离线、在线及查询总通信，从而避免重复计数或隐藏通信搬移。
23. 作为部署者，我希望看到首请求、setup 和完整会话成本，从而判断预处理在实际服务中的收益。
24. 作为研究者，我希望保留无法前移的输入相关协议成本，从而不把预处理描述成所有在线开销的消失。
25. 作为复现者，我希望保存构建配置、实际执行命令、材料覆盖和逐查询结果，从而复核新的对比。
26. 作为实验审查者，我希望失败、超时和内存不足保留真实状态，从而不把未完成实验计为零成本。
27. 作为论文作者，我希望区分在线延迟收益和端到端成本收益，从而让结论与证据范围一致。
28. 作为项目维护者，我希望继续延期 SDCF-09，从而先完成已确认的单时间步公平对照。

## Implementation Decisions

- **新增基线与共享策略。** 注册 SCI_preprocessed，保留默认 SCI 行；预处理能力作为原生 SCI 的共享执行策略，而非只对某个 ours 后端或某个控制组生效。SCI_ours 和 SCI_Beaver_segmented 在主对照中同样开启适用的原生 SCI 预处理，并记录实际模式。
- **数值与协议边界。** 使用冻结 mixed-width 图、`sci_compatible`、相同 `DIV_RESCALING`、符号扩环、截断舍入、输出环和调用顺序。SCI_preprocessed 保留原生 SCI 图级乘法及转换，不用 Beaver 或 FSS 替换其算法。公开 ScalarMul 保持公开本地乘法；Sigmoid/TanH 的原生数值算法保持一致。
- **复用既有模块接口。** 扩展现有后端 adapter、原生 SCI 上下文、材料生命周期、公开计划和计量模块。沿用 setup、prepare、enter_online、层调用与查询结束接口；避免新增独立 benchmark 入口。通过现有私有 SCI 构建覆盖机制实现，不修改工作区外共享 SCI 安装。
- **真实阶段划分。** Base OT 和持久上下文创建计入 setup。每次 prepare 必须在本次查询输入装载前完成一次性材料生成；模型权重按现有应用契约事先加载。不能使用本次查询输入或隐状态生成库存，也不能把输入之后实际执行的 OT、PRG 或三元组生成事后重分类。
- **公开材料计划。** 按实际后端、公开 shape、环宽、消息位宽、算子类型、worker 分块和通道方向生成材料需求。原生激活内部的 LUT、B2A、MUX、hadamard、截断、扩环及比较需求进入覆盖核算。被 FSS 或 Beaver 替换的原生在线调用不重复预备；Beaver/FSS 离线生成过程消耗的原生 OT 属于其离线成本，不再重复作为在线库存。
- **完整 OT 路径覆盖。** 处理普通 IKNP GOT、KKOT、多选一和混合消息位宽的批量 GOT，以及普通和批量算术 COT。仅设置普通 GOT 的缓存容量不能通过验收；当前直接扩展的批量路径和 COT 需提供对应随机材料适配。普通二选一随机 OT 在线选择修正逻辑上为每个 OT 一位，实际传输计入打包及尾部填充字节，并保留掩码消息通信；COT 按其实际模环相关性完成输入相关适配。
- **比较材料前移。** 在 prepare 中使用既有安全生成协议生成比较、wrap 和原生转换所需的标准或相关 bit-triple，不使用 Ideal 材料；在线比较继续执行原有输入相关步骤。其库存生成与消费应纳入相同覆盖报告，不能仅前移 OT 扩展而遗漏内部三元组生成。
- **上下文归属。** 原生图上下文、反向 OT、每个激活 worker 和独立图分支各自拥有对应材料库存与游标。两方使用一致的公开任务映射；库存归属不依赖线程完成先后。所有新增通道进入通信与资源计量。
- **材料生命周期。** 新鲜随机 OT、选择、掩码和 bit-triple 按查询生成并一次消费。缓存容量、装载与实际生成区分计量；prepare 结束意味着需求材料已经生成，而不是仅分配容量。严格预处理模式在 online 禁止生成或补充库存；不足、错配或剩余未说明材料不能静默回退或参与合格主表。SIMD 与分块产生的 padding 单独记录，区分有效消费和公开填充余量。
- **资源与存储。** 沿用每方四核、1.5 GiB RLIMIT_AS。材料可使用受预算约束的连续内存或已生成的磁盘库存；输入后的读取、装载和等待保留在在线及查询总成本中。记录库存规模、生成/消费/剩余量、峰值 RSS、存储方式和输入后补充次数；预处理不能借用额外未计入的计算参与者。
- **匹配主表。** 每个共享调度 cohort 至少重新测量默认 SCI、SCI_preprocessed、SCI_ours（开启共享原生预处理）和 SCI_Beaver_segmented（开启共享原生预处理）四行。直接比较 SCI_preprocessed 与两个明确命名的 ours 行；默认 SCI 用于说明默认实现到预处理实现的变化。ours 未开启共享预处理的模式可作为必要归因对照，不要求所有优化开关全排列。历史结果仅作为历史参考，不混入新主表。
- **主环境。** batch=128、单时间步、localhost 为主环境。分别使用现有 a4-sequential 与 a2-parallel 共享调度：前者顺序图与激活上限四，后者两分支各最多两个计算参与者。服务方 CPU 为 0,2,4,10，客户端为 6,8,12,16；Eigen、OpenMP、协议线程和材料 worker 均纳入总配额。资源不可用时保留原因，不把不同资源行标成匹配结果。
- **重复与时间预算。** 主表每行十个 fresh query、warmup=0；沿用每行 600 秒时间预算。正式性能行串行执行，并与编译或其他重负载隔离。定位协议问题的小规模测试不替代 batch=128 正式行，也不作为加速主张来源。
- **结果结构。** 每行记录实际预处理覆盖、setup、offline/material-ready、输入/ready、online、output、直接 query total、首请求和 session total。逐查询先取双方最大时延，再统计中位数、min/max 和离散程度；直接总时间独立测量，不把阶段中位数相加。通信使用双方发送字节之和，实际依赖轮数与 socket 调用次数分开。
- **归因与结论。** 分别报告默认 SCI→SCI_preprocessed 的收益，以及 SCI_preprocessed→各 ours 的在线时延、在线通信、离线和总成本变化。用覆盖与实际字节解释前移了哪些工作；不能从历史在线时延减去理论 λ 项来估计新时间。若波动范围不足以支持排序，保留不确定性；若预处理后 ours 无优势或总成本增加，也如实报告。

## Testing Decisions

- **主验收 seam。** 在既有真实两方 FastGRNN 单时间步入口验收：同一公开计划经过 prepare、输入装载、在线计算和查询结束，观察整数输出、阶段日志、通信、材料覆盖及失败状态。优先复用已有两方 runtime、非零隐状态、覆盖和比较测试，不以内部函数调用次数代替协议行为。
- **整数一致性。** 所有主表后端在 batch=128 下分别完成默认和非零隐状态诊断，与默认 SCI 核对现有 15 张量、172928 个整数；正式性能关闭中间张量揭示。改变输入数据而保持公开计划，核验预处理需求和覆盖不依赖本次输入。
- **协议边界。** 通过已有两方原语或完整转换测试覆盖二选一/多选一、普通及批量 GOT、算术 COT、混合位宽、非整字节尾部及比较 bit-triple。核验普通随机 OT 的选择修正与选中消息、算术 COT 的原有环相关性，以及负数截断、wrap 和符号扩环行为；仅添加协议改造涉及且高层正常样本不能覆盖的必要用例。
- **阶段与生命周期。** 两方执行日志证明 prepare 在查询输入装载前完成，所有在线使用材料已经生成。严格模式下记录在线扩展/库存补充为零；通过真实执行覆盖库存不足、错配、跨查询重复消费以及查询结束消费核对。材料失败不能静默换成默认 SCI 成功结果。
- **上下文与资源。** 在顺序和两分支模式分别核验激活 worker 的整数结果、库存归属和通信计量；确认实际计算参与者不超过既定配额。内存或库存装载成本按发生阶段记录，不用小规模完成替代 batch=128 资源验收。
- **正式复测。** 正确性通过后按已冻结四后端、两 cohort、每行十查询配置执行新样本；保存逐查询日志、命令、构建配置和材料覆盖。验证双方最大时间聚合、发送字节和及直接 query total。保留超时、OOM、不支持或不可用的状态与 null 完成成本。
- **验收标准。** 交付条件是完整覆盖、正确性、真实阶段划分、匹配资源及可审阅结果；不要求实现预设加速比例。未覆盖的可预处理调用要明确列出，不能把普通 GOT 局部缓存结果命名为完整 SCI_preprocessed 对照。

## Out of Scope

- SDCF-09 的 99 步安全整图、分类头、ArgMax、Google-30 Top-1 与整网质量验收继续延期。
- 不更换模型、训练参数、量化策略或整数语义，不把 SCI_preprocessed 改造成 Beaver/FSS 乘法或转换基线。
- 不引入经销方、额外可信假设、恶意安全扩展或重复使用一次性材料。
- 不要求新的段数搜索、激活近似算法、全优化开关排列、跨查询流水或吞吐优化。
- 本轮正式主表聚焦 localhost；LAN/WAN 补充不是本规格的必需交付。
- 原规格发布阶段只整理需求；本轮 01–08 的代码实现、资格验收与基准复测均已完成，交付证据见上方链接。

## Further Notes

- 普通二选一 IKNP 在仅完成 Base OT 时，每个 OT 的通信约为 λ+2b；λ 项来自包含选择向量的 U 修正矩阵。提前完成随机 OT 后，普通 GOT 可把约 λ bit/OT 扩展通信移到离线，在线仍需约 1+2b bit/OT；此说明不直接替代批量 COT、多选一或整图实测。
- 公平比较要求双方获得同样的输入前预处理机会、资源及安全假设，不要求双方离线耗时相同。所有一次性材料仍按查询计费；setup、首请求和持久会话另列。
- 历史 batch=128 单时间步并行配置中，默认 SCI 在线约 1.149810 s，Beaver+分段 FSS 在线约 0.469814 s，后者离线约 6.095547 s、直接 query total 约 6.570007 s。这些仅用于说明本次补充基线的动机，不是 SCI_preprocessed 的测量或收益承诺。
- 项目沿用本地 Markdown 工单方式发布；原始 `ready-for-agent` 状态表示可交付实现，现已在 01–08 验收后关闭。本规格按用户显式调用的 to-spec 技能整理，并按 implement-spec 完成交付。
