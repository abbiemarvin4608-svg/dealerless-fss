## Problem Statement

当前框架在 SCI/SiRNN 的冻结定点图上，分别接入分段 DPF-based DCF 转换和 Beaver 乘法。常驻 cGGM 线程池已经降低线程创建与短任务调度开销，但转换协议、密钥材料读写和图调度仍有可避免的串行工作。用户需要进一步降低 Batch=128 的在线时延、离线开销和峰值内存，并能判断每项收益来自通信合批、数据布局、分段策略、计算并行还是乘法预处理。

现有替换范围如下：

| 后端 | 图级 MatMul / MulCir | 图级截断和扩环 | Sigmoid / TanH 内部 |
| --- | --- | --- | --- |
| SCI | 原生 SCI | 原生 SCI | 原生 SCI |
| SCI_ours | 原生 SCI | 分段 FSS 转换 | 原生 SCI |
| SCI_Beaver | Beaver | 原生 SCI | 原生 SCI |
| SCI_Beaver_segmented | Beaver | 分段 FSS 转换 | 原生 SCI |

分段 DCF 的比较主要服务低位借位、符号和回绕修正，并未替换全部比较或激活内部协议。Google-30 的公开 ScalarMul 保留本地乘法，其转换可以被替换。

2026-10-10 同环境单时间步测量中，组合后端在线中位数为 1.342974 s、离线为 6.371501 s；相同组合后端单线程在线为 1.411442 s。两段宽域单步在每方 1.5 GiB 地址空间预算下 OOM。原生激活的已有粗粒度计时约占组合后端在线时间的 55%。这些是基线证据，不是本规格的收益承诺。

主要问题是：

- low/sign/wrap 比较输入同时可用，但三次完整 scan 串行执行。
- 每次在线转换都读取并重建大量密钥，再为每段分配查询 bit 数组。
- 全局段数策略不能同时利用窄域两段的在线优势和宽域四段的内存优势。
- Beaver MulCir 两个独立扩环串行执行，服务方矩阵乘法还包含可代数合并的本地乘积。
- Boolean 消息按字节保存单个 bit，cGGM 每个 worker 内仍主要逐 key 调用单块哈希。
- 离线深树批量展开同时保留全部节点与哈希，造成内存峰值。
- 原生激活、图分支和材料准备的并行受到共享协议通道、当前层状态和材料游标限制。

## Solution

在现有数值契约和两方无经销设置下，分阶段实现可独立验证、可单独计量的优化。保持 SCI、SCI_ours、SCI_Beaver、SCI_Beaver_segmented 四路对照，并保留完整树和固定段数作为可行范围内的原语参考。

实施按以下顺序推进：

| 阶段 | 工作内容 | 进入下一阶段的条件 |
| --- | --- | --- |
| A：通信与数据布局 | 修正计量和日志；多域 scan 合批；MulCir 双输入扩环合批；连续材料与工作缓冲；Beaver 本地代数合并 | 两方整数一致、材料消费正确、相关阶段和通信计量完整 |
| B：计算与内存 | 按域分段策略；Boolean 位打包；批量 AES；按预算分块生成离线树 | 固定与混合段数逐值一致，实测资源曲线和各项成本可解释 |
| C：算子与调度并行 | 原生激活的独立协议 worker；图分支调度；离线材料流水与 tile 调优 | 共享状态已拆分，总 CPU 配额一致，匹配的 SCI 控制组和阶段核算通过 |

每阶段都产生正确性结果、性能对照和配置建议。优化变慢或未达到资源目标时保留实测结果，不以获得预设加速比例作为交付条件。未经验证的模式不成为默认配置。

## Implementation Decisions

### A0. 保持契约并补齐计量

- 复用现有 SCI-compatible 转换、分段 DCF、Beaver、两方桥接及 runtime 接口。核心数值接口保持输入/输出环宽、符号解释、缩放位置、舍入方式和输出顺序。
- 保留公开 ScalarMul 本地乘法；不把公开参数改成私密输入制造额外对照。Sigmoid/TanH 保持原生 SCI 数值算法，本规格优化其执行方式。
- 继续使用已完成的常驻 cGGM 池；短批次按工作量在调用线程执行。日志区分 worker 上限与实际参与者数量。
- 修正 Beaver 和公开 ScalarMul 中写死的转换来源；每次调用记录实际后端、实际比较域、段宽、调用分组和消费数量。
- 增加材料装载/反序列化、查询位准备、local eval、scan、rounding、B2A 和释放的定位计量。整体 online 必须覆盖输入确认后发生的全部这些工作；子项缺失不能解释为零开销。
- setup、offline、材料准备、input/ready、online、output、直接 query total 和 session total 各自有明确边界。并行子任务的工作时间可以重叠，不相加冒充墙钟时间；线程计数和通信计数使用各 worker 的独立记录再汇总。

### A1. 多域 DCF 按通信层合批

- 在内部把比较执行拆成局部子树求值、当前 scan 层准备、统一交换和当前层完成。通过现有完整转换接口对外提供相同结果，不暴露要求调用者手工管理 scan 层的新公共 API。
- low/sign/wrap 在输入可用后共同进入调度；同一深度已就绪的 AND 打开拼成一次消息，各域保留自己的材料区间和输出映射。
- 一组独立域的 scan 依赖深度从各域层数之和变为最大层数。三域均四段、包含向零修正的 signed div_pow2，从打开1轮、scan6轮、rounding1轮、B2A1轮，变为1+2+1+1，共5轮。
- 不把上一层产物尚未产生的 AND 放入同一次普通 Beaver 打开。零位域跳过，不均匀段数和奇数 scan 节点保持比较次序。

### A2. MulCir 的独立扩环合批

- 当两输入均就绪且 input/output bits、符号、数值模式及转换操作相同，将两组扩环连成一次批量转换，输出按确定顺序切回两操作数。
- 同步修改转换计划、离线材料规模、桥接消费和覆盖记录；异构契约按契约分组，有数据依赖的调用保持依赖。
- 当前两次各6轮的扩环，单独启用本优化时应变为一次6轮；与多域 scan 融合同时启用后，按实际执行计划重新计算轮数，不将两项收益重复相加。

### A3. 连续材料、工作缓冲和有界预取

- 将批量密钥的 correction words 与元数据改为连续存储或可连续读取的布局，减少逐把小读取和堆分配。现有公共调用形式可以保留，由内部批量视图承接。
- 在线 eval 优先直接从公开 query 按公开 shift/width 读取所需位，或使用连续 bit 缓冲；不再为每个段构造独立查询向量。
- 每次调用使用受所有权管理的 scan scratch 和 level 缓冲，可跨查询复用容量；keys、mask、triples 仍按一次性材料消费。
- 首先消除复制与小分配，再实现受预算限制的材料预取。必须记录驻留字节和装载时间，避免一次性把全时间步材料全部载入内存。
- 预取本查询材料若发生在输入确认前，计入 offline/material-ready 并包含在 query total；输入确认后才发生的等待和读取计入 online。为归因提供与基线相同边界的装载成本和直接总时延，不能仅通过改变计时起点宣称收益。

### A4. Beaver 本地乘法代数与存储优化

- 保持现有 E/F 一次批量打开和一次性三元组消费。服务方利用矩阵乘法分配律合并 E 乘本地 v 与 E 乘公开 F，服务方从三次本地矩阵乘变为两次；客户端保持两次。
- 所有矩阵加法和乘法遵循原有模二次幂环语义，不改变符号扩环、累加器宽度和后续截断契约。
- 结合现有 Eigen 路径，使用正确的行列布局视图和可复用输出缓冲，减少输入输出复制。不能为减少复制引入输入输出别名错误或改用浮点矩阵乘法。
- 大矩阵块的本地并行继续遵守每方总 CPU 预算；先测代数与布局收益，再决定是否增加 worker。

### B1. 按域分段策略

- 保留 fixed-2、fixed-4 两种策略，实际段数仍受域宽限制；另外新增公开的 depth-cap-8 策略，各非零域使用满足最大段宽不超过8的最少段数。
- 当前域宽1至8对应一段，9至16对应两段，17至24对应三段，25至32对应四段；零位域不执行比较。始终记录实际段数及高位优先连续段宽，支持不等宽段。
- 配置中的 low/sign/wrap 独立段数同时进入离线计划、序列化和在线契约检查。策略只依赖公开域宽、shape 和显式资源预算，不依赖秘密输入或最终评估结果。
- 混合策略是固定候选，不预设优于 fixed-4。尤其与多域 scan 融合同时启用时，最深域决定通信层数，窄域少分段未必进一步减少轮数。

### B2. Boolean 位打包和批量 AES

- 增加内部布尔批量交换能力，用 packed bits 承载 scan 的 E/F 和转换 correction 打开；普通 byte 接口语义保持稳定。
- 同一条消息含 N 个布尔值时，数据载荷按向上取整的 N/8 字节计量，消息头若存在单列；双方采用一致的 bit 顺序和尾部处理。
- 删除 byte、GroupElement、uint64 中转复制。只复用传输工作缓冲，保留独立且新鲜的布尔材料。
- 在每个连续任务块内将多条 cGGM 路径按深度推进，复用已有批量 AES 实现，保持相同固定密钥哈希定义。离线整层节点和叶子哈希也使用相同批量内核。
- 保留混合深度映射和原输出顺序；公开路径方向允许的叶子哈希裁减需与批量版本独立核对。改进吞吐不能以改变密码学参数或哈希函数换取。

### B3. 离线树生成分块

- tile 大小由公开 batch、段宽、节点/hash 缓冲估计、已驻留材料和总内存预算决定。不能仅按最终紧凑 key 大小估算峰值。
- 一块完成后释放展开树，保留该块最终 keys 和对应材料顺序；必要时写入连续材料存储。根、mask、triples 按原协议新鲜生成。
- 目标是在每方1.5 GiB地址空间预算内执行32位、两段、count12800 的离线比较，并尝试完整 Batch=128 单时间步。
- 如为减小常驻 hash 缓冲而重新计算哈希，额外哈希次数必须记录；逐 tile 完成整个 keygen 导致的新增通信批次/轮数也必须记录。
- 分块只解决工作集规模，不改变深度16的指数级总展开量。若公开预算下仍超时或资源不足，记录受限状态和失败位置，不填入完成时延或宣称目标已通过。

### C1. 原生激活并行

- 独立配置 activation worker 数，默认对照1、候选4；以连续元素区间切分 Sigmoid/TanH，保持完整向量输出顺序和数值算法。
- 每个 activation worker 拥有独立 SCI Math/IO/OT 上下文及固定两方通道映射。不要通过单独修改全局线程数把尚未支持分片的 Beaver/conversion hook 送入多线程执行。
- 原生激活内部调用仍明确路由至 native SCI；并发日志和计数应按 worker 收集后输出，避免共享当前层与游标竞态。
- 单参与者直接调用，多参与者使用常驻 worker；各优化后端及原生 SCI 控制组使用相同 activation 配置。
- 初始化多个协议上下文计入 setup；实际通道的流量和内存纳入总计。显式 OpenMP 内部线程也需记录，不能把环境变量值当成实际线程数。

### C2. 图分支并行

- 在单时间步真实数据依赖图上调度输入投影与隐状态投影两条链，以及共同线性输出之后的两条激活分支。循环时间步之间仍保持递归依赖。
- 前置条件是按任务拆分当前层状态、转换计划、材料游标和协议连接；复用同一连接的工作必须经有序的协议调度器串行发送，不能直接并发读写。
- 先选择按依赖层合并独立 opening，再评估独立通道执行分支。主候选固定为两条并发分支、每条最多两个计算参与者；每分支的activation和cGGM上限均为2，不叠加每分支activation=4或另一个四线程内核。
- 共用计算配额调度器约束同时活跃的worker，显式OpenMP或库内并行也纳入分支配额。仅设置四核affinity不足以验收此项；日志同时保存请求与实际并发配置。不能满足配额的模式记录为unsupported，不以超额唤醒的结果进入该对照行。
- 图调度是四路后端共有能力；对照采用相同依赖层和 CPU 预算。并行模式的覆盖检查根据依赖与唯一调用身份验证完成情况，不再假定日志总是串行顺序。

### C3. 离线材料流水与 tile 调优

- 分别评估矩阵 Beaver OT 的公开行 tile 大小，以及 Beaver 与 FSS 材料在独立通道上的重叠准备。多个任务不能共享同一个有状态 LinearOT/IOPack 并发运行。
- 所有并发准备共享每方1.5 GiB和四核预算，避免 cGGM、Eigen、OpenMP 和协议线程分别申请完整线程配额。
- 首先实现同查询离线准备的重叠；跨查询预取作为独立可选模式，仅在明确分配新鲜材料和建立有界队列后启用。
- 流水结果单列首请求延迟、逐查询材料生成成本、会话墙钟时间和稳态吞吐。重叠区间不重复累计为墙钟成本，也不把隐藏在前一查询后的离线成本记为零。

### 实施依赖与默认配置

- A0 在所有计量前完成。A1 与 A3 可以独立推进；A2 依赖转换计划合批能力，和 A1 集成后重新核对轮数。A4 可以独立推进。
- B1、B2 在数值与通信回归通过后分别集成；B3 是完整 fixed-2 宽域运行的前置。连续布局与批量 AES 同时修改数据视图时由同一接口契约协调。
- C1 优先于 C2；C2/C3 在上下文、通道和资源预算可独立管理之后推进。各阶段有自己的消融配置，不要求所有开关的笛卡尔积。
- 原有 verified 模式始终可以作为对照。新模式通过正确性和对应资源验收后，依据预声明的在线/离线目标选择推荐配置；没有满足预声明推荐准则的收益时保留原推荐设置。

## Testing Decisions

### 已确认的验收接口

用户已确认：以现有两方 Batch=128 单时间步运行入口作为最高验收接口，补充现有 DCF、完整 SCI-compatible 转换和 Beaver 原语接口。复用已有小域穷举、真实两方整数重构、bridge 一次性材料消费检查和非零隐状态逐算子诊断；不增加仅为测试暴露的内部 scan/pool API。

好测试检查输入对应的重构结果、协议承诺的通信深度、实际传输载荷、一次消费和公开资源行为。线程池内部容器、精确函数调用次数或特定内存分配顺序不作为接口正确性断言。性能变化通过基准证据验收，不通过机器相关的绝对毫秒阈值判单元测试成败。

### 冻结实验环境

- 使用当前机器、编译器、Release配置、冻结模型和量化输入；服务方CPU为0,2,4,10，客户端CPU为6,8,12,16。每方总预算四个已核对拓扑的核心，保留原生SCI和优化后端相同配额。
- 每方地址空间上限1.5 GiB；正式测量串行运行，避免编译或其他重负载并发。cGGM对照上限为1/4，激活对照worker为1/4；实际参与者、所有协议通道和内部并行设置一并记录。
- 主对照使用不整形localhost。通信合批补充使用现有sirnn_lan与wan模拟配置，分别为RTT 0.8 ms、3016 Mbps和RTT 2 ms、100 Mbps；新协议通道必须全部经过对应链路和计数，不能漏掉并行通道。不同网络结果分表。
- count128的16位DCF每行30个新鲜查询；count12800的16位DCF每行10个新鲜查询；32位输入、shift14的完整转换每行5个新鲜查询；单时间步每行10个新鲜查询。均无预热，每次重新生成并消费一次性材料。
- 单时间步重复数由历史5次增至10次，所有匹配基线同步重测；历史数字只作为来源明确的背景，不能拼接进新样本。基本原语/转换每行120秒、宽域分块验证和单步每行600秒的墙钟预算在运行前冻结。
- 时延先对齐查询取双方最大值，再统计中位数、min/max及离散程度；通信为双方发送字节之和。保存原始样本、setup、offline、online、直接query/session total、首查询、峰值RSS及可分离的逻辑轮数。
- 若不确定性大于观测差异，报告中位数变化及范围，不能仅凭重复查询中位数声称统计显著。任何扩展重复或资源预算作为新的预声明实验保留原结果，不追加到有利为止。

### 对照矩阵与消融

| 轨道 | 固定比较内容 | 目的 |
| --- | --- | --- |
| 基线锚点 | 当前已验证四路后端，转换fixed-4，cGGM上限1/4适用行，activation=1 | 重新确认当前成本和新计量边界 |
| 16位DCF | count128/12800 × fixed-2/fixed-4 × cGGM上限1/4，优化前后匹配 | 区分短任务、真实向量并行和scan成本 |
| 完整转换 | input/output32、signed div_pow2、shift14、count128，fixed-2/fixed-4/depth-cap-8 | 同时覆盖low14/sign31/wrap32，避免只测低位比较 |
| 宽域资源 | 31/32位、count12800、fixed-2，分块前后；固定四段作为资源参照 | 验证OOM改善、额外离线工作与时间预算 |
| 转换调度 | 当前版本、仅A1、仅A2、A1+A2，其余配置相同 | 验证域内/跨调用通信收益及两者组合 |
| 本地内核 | A3、A4、bitpack、批量AES分别对各自前置基线，以及累计集成版本 | 区分数据布局、代数、载荷和吞吐收益 |
| 段数策略 | 完成配置中的fixed-2/fixed-4/depth-cap-8，其他优化相同 | 比较在线、离线、总成本与内存；失败行保留 |
| 激活并行 | 四路后端分别activation=1/4，其他配置相同 | 公平比较SCI并行与新增后端收益 |

每项只跑对应行为及受影响性能轨道。交互明确的A1+A2、布局+AES、分段+tile和激活+图调度需要组合验证，不要求全部开关全排列。通信补充网络仅测融合前后相同配置，不扩大为所有内核的多网络穷举。

完成行需具备正确性、实际调用覆盖和完整成本记录。失败行使用oom/timeout/unsupported/unavailable等真实状态及null完成时延；不能用count128的两段数据替代count12800或完整单步数据。收益、持平、回退都进入报告。

## Out of Scope

- SDCF-09：99个递归步、分类头及完整评估集的安全整图正确性和Top-1质量验证继续延期，不因本规格的单步验收改为通过。
- 重新设计激活近似、修改量化尺度/位宽、改变公开私密输入属性、替换模型或调整最终评估数据。
- 使用高阶相关预处理实现单个多段比较的一轮合并，或声称普通二元Beaver能直接消除跨层依赖。这属于另一个协议设计规格。
- 引入GPU、分布式集群或新的密码学安全模型；本规格聚焦当前CPU两方执行框架。
- 把一次性材料跨查询复用，或把离线成本从总计中删去以获得在线加速结论。
- 修改论文的整图性能/质量主张。本规格交付代码与实验记录，论文更新需另按实际证据范围处理。
- 方案发布阶段不同时执行实现、拆分正式实施工单或启动基准测量；发布后经用户授权，实施按本规格及相应工单推进，完成记录见[执行记录](EXECUTION.md)。

## Further Notes

### 术语与证据范围

- cGGM/DPF描述密钥材料，DCF描述比较语义，完整conversion包含掩码打开、low/sign/wrap比较、舍入与B2A修正。混合段数改变协议成本，不改变整数语义。
- `Batch=128`是128条独立序列；每样本100维向量形成count12800，二者不能互相替换标注。
- 现有常驻池对16位count128短路径可能只使用调用线程，对count12800才使用四个参与者。日志与结果按实际参与者解释。
- 原生激活约55%的占比来自历史粗粒度日志，仅用于确定优化优先级。现有1.342974 s等数值来自旧五查询测量，不作为新实验的通过阈值。
- 本规格分为方案发布与后续实施。发布时仅标记规格 `ready-for-agent`；后续实施现已完成，结果及限制见[最终报告](../../project/our/results/runtime_optimization_20261010/REPORT_CN.md)。SDCF-09 以及依赖整图质量的历史工单继续保持原状态。
