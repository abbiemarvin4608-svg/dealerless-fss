# 10: 测量比较位宽与分段数成本曲线

**What to build:** 对实际两方私密比较/MSB 调用执行位宽和分段数 sweep，量化 SCI 原语与分段 FSS 原语在真实调用中的延迟、通信和资源曲线，并产出后续 Google-30 端到端配置选择依据。

**Blocked by:** #04 打通 SCI 真实推理的完整计量；#05 在 SCI 中接通一次分段比较或 MSB

**Status:** completed

- [x] 每个 sweep 点都通过真实两方私密输入调用执行，不能以本地明文循环、静态公式、空协议或只改变配置不发起调用的结果替代。
- [x] 覆盖原生图真实比较域宽和 16、20、24、32 位，包含预先冻结的多个分段数与可完成的单树对照；每个点记录实际分段数、批大小和比较/MSB 调用次数。
- [x] SCI 原语与分段 FSS 在相同输入分布、数值语义、线程、batch、网络和安全参数下成对测量，保持输入私密和输出规则一致。
- [x] 每个可完成配置报告 offline、online、total 延迟、双方通信、依赖轮数和峰值内存，并拆出密钥生成、输入转换、跨段合并和输出重构成本。

- [x] 预先规定重复次数、预热、超时和内存预算，分别记录 LAN/WAN 结果及中心趋势和离散程度。
- [x] 对超时或资源不足的 sweep 点保留资源上限、已完成调用数和失败原因，不将其转换成虚构时延或通信值。

## 执行结论（2026-10-08）

`complete` profile 已完成两种网络模型上的完整位宽×分段矩阵：宽度 `2,9,16,20,24,25,32`，SCI 单树以及所有合法 `ours,nseg={1,2,4,8}`（宽度2仅 nseg=1），每点 1 次预热 + 3 次重复。共 64 个网络/点组合、256 条原始运行记录；232 条完成。宽度24/25/32 的 ours 单树在预热真实触发 `std::bad_alloc`，其失败日志、资源限制、退出码和后续 `not_run` 行均保留，未做延迟填充。
