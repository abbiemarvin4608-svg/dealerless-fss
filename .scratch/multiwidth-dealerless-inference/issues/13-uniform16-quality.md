# 13: 完成统一存储 16 位精度闭环

**What to build:** 在同一 Google-30 模型和独立评估流程上完成统一存储/I-O 16 位的精度控制组，用逐张量尺度和合法扩宽算术隔离存储位宽影响，形成可与原生混合位宽比较的质量产物。

**Blocked by:** #01 回放 Google-30 原生整数图并冻结数值契约；#02 生成独立评估的 Google-30 质量产物

**Status:** ready-for-agent

- [ ] 单独报告相对约定参考的数值误差，注明比较张量、尺度、单位和统计方式；数值误差与 Top-1、agreement 分开，不以分类指标替代。
- [ ] 所有被纳入控制的张量存储和算子 I/O 使用 16 位表示，同时允许必要的乘积、累加和中间函数计算扩宽；该配置明确标为 storage/I-O uniform-16。
- [ ] 不把所有运算强制限制在同一 16 位环；严格同环行为留给后续诊断，避免将环回绕或禁止扩环造成的错误解释成存储位宽结论。
- [ ] 每个张量保留独立、可追溯的小数位或尺度，按冻结的校准数据选择并在独立评估前锁定；测试集不得用于事后挑选尺度。
- [ ] 使用 #02 的同一 FP32 模型、权重与数据，沿用 #01 的契约定义，保持激活近似、截断和舍入规则可比；转换/饱和规则写入新契约。导出完整整数图并回放，不能仅修改容器类型或配置标签。
- [ ] 在 #02 独立评估集上报告 Top-1、相对 FP32 的 loss_pp、prediction agreement、溢出/饱和/截断统计，并判定是否满足 1.0 pp 主门槛。
- [ ] 与 native mixed-width 产物使用同一标签映射、样本顺序和 FP32 checkpoint，输出逐样本预测及首个异常样本的张量和尺度信息。
- [ ] 产出可复现的量化配置、尺度表、预测文件、质量摘要和失败原因；质量未达标时保留完整结果但不得进入达标配置的性能排名。
- [ ] 本工单只证明统一存储/I-O 16 位的数值行为，不将其结果写成安全端到端性能或严格同环诊断结论。
