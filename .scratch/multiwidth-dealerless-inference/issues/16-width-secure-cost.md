# 16: 比较位宽配置的真实安全成本

**What to build:** 在 Google-30 已完成的安全后端和位宽曲线基础上，测量 native mixed-width、统一存储/I-O 16 位和 32 位的真实安全成本，并对适用的算子比较直接宽域计算与“转换/缩环后窄域计算”的总成本。比较依据已冻结的数值语义和质量结果，不预设转换路径必然更贵。

**Blocked by:** 07: 完成 SCI + ours 整网一致性；09: 完成 MP-SPDZ Google-30 安全推理；10: 测量比较位宽与分段数成本曲线；14: 完成统一存储 32 位精度闭环

**Status:** ready-for-agent

- [ ] 选定 native mixed-width、统一存储/I-O 16 位和 32 位中通过 Top-1 损失不超过 1 个百分点的配置，并为每行保留同一 FP32 参考和 prediction agreement。
- [ ] 为 SCI/SiRNN OT、SCI + ours 和 MP-SPDZ 的已接通位宽配置分别完成安全执行与正确性核验，冻结输入输出尺度、累加宽度、截断、激活近似和比较输入宽度。
- [ ] 直接宽域与转换/缩环加窄域的同语义配对通过整数一致性验证；改变数值语义的配对单列为系统轨并各自通过质量门槛。语义或质量结果不明确的配对标为不可用并说明原因，两侧均允许合法融合和局部操作。
- [ ] 将扩环、重定标、缩环、输入转换、分段密钥生成、跨段合并和恢复操作计入相应阶段，统计每类调用次数和实际位宽。
- [ ] 在相同机器、线程、batch、输入顺序和 LAN/WAN 条件下重复测量，分别记录 offline、online、total 延迟、通信量、依赖轮数和峰值内存。
- [ ] 同时给出首查询成本与跨查询摊销成本，标明预处理总查询数、摊销规则以及不可摊销的密钥、掩码和三元组消耗。
- [ ] 生成可追溯的位宽成本表和原始日志，能从结果行定位到数值契约、分段数、后端版本和测量边界。
- [ ] 对超时、内存不足、精度不达标或后端未接通的配置保留 `status/reason`，不得用 smoke、结构耗时或零值填充安全成本。
- [ ] 在分析中分别报告直接宽域和转换后窄域的收益与代价，不预设任一路径必然更快，也不把单一任务结果推广为普遍最小位宽结论。
