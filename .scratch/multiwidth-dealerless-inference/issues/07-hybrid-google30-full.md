# 07: 完成 SCI + ours 整网一致性

**What to build:** 实验维护者可以在独立评估产物的完整固定测试清单上运行 SCI 与 SCI + ours Google-30 安全推理，完成全部 99 个时间步和分类头，并获得逐算子核验及完整定点预测向量完全一致的证据。

**Blocked by:** 02 — 生成独立评估的 Google-30 质量产物；06 — 验证 SCI + ours 单个 FastGRNN 时间步。

**Status:** completed

- [x] 使用工单 02 冻结的模型、量化配置、预处理、标签映射与测试顺序，核对其契约与已接入接口兼容；若变化影响语义，更新并重新通过对应时间步核验，不用历史模型输出替代新配置参考。
- [x] 两个真实安全后端均完成 99 个 FastGRNN 时间步和分类头，保留模型由服务方、输入由客户方持有的两方无经销者执行方式与原生输出揭示规则，后端名称明确为 SCI 和 SCI + ours。
- [x] 在独立核验模式覆盖整图内每类已替换算子，比较重构整数结果、递归隐状态和分类输出；记录实际分段调用覆盖情况，确保既定替换没有在循环或分类头中静默退回 SCI。
- [x] 对完整固定测试清单实际执行安全推理，保存 SCI、SCI + ours 与同图定点参考的逐样本预测向量，要求 SCI + ours 与 SCI 的预测完全一致并核对参考结果；历史 30 条样本不能充当完整清单。
- [x] 支持长任务按样本或独立批次保存进度并恢复，结果绑定模型、数值契约、后端及样本身份；汇总检测缺失、重复和版本混用，重跑失败样本时生成新一次性材料。
- [x] 任一差异报告首个相关样本、时间步、算子、张量、位宽、尺度与数值，修复并重验后才可通过；Top-1 恰好相同、误差解释或少数差异均不能替代完全一致要求。
- [x] 汇总 FP32/定点 Top-1、loss_pp、FP32 agreement、基线 agreement、数值误差、成功样本数及失败原因；引用工单 02 的参考定义与误差口径。未达到 1.0 pp 门槛的配置保留记录并禁止进入达标性能排名，质量门槛与协议一致性分别判断。
- [x] 保存完整安全执行日志、逐样本结果、算子一致性报告和复现命令，区分诊断揭示与正式安全运行；只有无缺失且整图一致性通过，才将本配置交给后续性能对照。
