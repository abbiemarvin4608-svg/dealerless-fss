# ResNet 实验实现核查

范围是本轮驱动、桥接和复用协议的代码数据流；本记录不等同于完整密码学安全证明。

## 输入、模型与离线边界

- `secure_driver.cpp` 的 `load()` 仅在服务方载入权重；`input()` 仅在客户方载入输入。
- `run()` 先完整执行 `prepare()`，再执行输入载入与在线推理。材料生成只接收公开的算子形状与调用计划。
- SCI 的 `Alice_has_A` 线性层通过 OT 处理客户方输入份额，通过本地乘法处理服务方输入份额；没有将模型权重公开。
- Beaver 的 `prepare_matmul()` 私有生成 U、V，以 OT 计算交叉项；在线仅打开掩码差值并执行标准修正。
- CNN、截断和矩阵材料均在每个 query 生成并消费；结束时检查调用库存，关闭矩阵材料文件并重置游标。正式运行只向客户方打开最终输出，不导出中间份额。

## 通信统计

- 原生 SCI、CNN 桥接和截断桥接分别计量，驱动快照合并三者。
- 桥接包含原始 Peer 套接字与三个 NetIO 通道，基础 OT、扩展 OT 和 BooleanAnd 的直接 KKOT 均有计数路径。
- 原生、桥接 NetIO 与原始 Peer 使用不同轨迹通道编号。桥接符号隐藏与本地绑定避免计量符号互相覆盖。
- 未发现活跃通道漏记或重复计数。每个正式结果还必须通过双方发送/接收、阶段轨迹字节一致性与全部 1,000 个输出整数的核对。

## 随机种子修复

原生 SCI 默认 `PRG128` 种子路径调用 `_rdseed64_step` 而未检查返回值。Beaver 每批材料直接使用此默认构造器，因此不能无条件声称失败时仍获得新熵。

本轮构建将原生与桥接统一设置 `EMP_USE_RANDOM_DEVICE=1`。反汇编核对确认两个最终产物不再保留直接的 RDSEED/RDRAND 指令，保留的默认构造器均调用 `std::random_device`。本机 GCC 9.4 所用 libstdc++ 6.0.28 对硬件随机源检查成功状态并重试，持续失败时抛出异常；文件后备路径处理短读与 EINTR。因此这是带失败处理的库随机源，不是仅使用操作系统随机源。算术、通信流程和 GPU 整数精度结果不受该编译开关影响。

## 剩余实现限制

继承的 Peer `send_block`/`send_ge` 等旧接口存在单次 POSIX send 后按请求字节计数的路径；短写或 EINTR 可能使执行和计数失效。当前活跃的 `send_u8` 路径有循环发送，已通过的输出核对未显示这类故障。正式结果需要保留输出审计和完整轨迹通过记录。
