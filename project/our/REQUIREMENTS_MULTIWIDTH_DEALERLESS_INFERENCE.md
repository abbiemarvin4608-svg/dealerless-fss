# 多位宽两方无经销隐私推理需求

状态：已确认需求，待实现与验证

日期：2026-10-08（Asia/Shanghai）

本文按 to-spec 结构固化本次讨论。已确认的研究决策作为实施依据；线程、batch、网络参数等未定执行参数在运行前配置。本需求取代旧计划中“统一 32 位必需”和不匹配的比较口径，历史结果保留原配置与来源。

截断专项需求见 [分段 DPF-based DCF 截断需求](REQUIREMENTS_SEGMENTED_DPF_DCF_TRUNCATION.md)。该专项将当前完整树 DPF-based DCF 截断升级为论文域分段实现，并固定 SCI 兼容整数语义、Beaver 归因控制和 Top-1/agreement 质量门槛。

## Problem Statement

当前论文把 32 位描述成共同推理宽度，但现有证据不能支持“所有 CNN/RNN 都必须统一使用 32 位”。SiRNN 的核心做法是让输入、权重、累加器、数学函数接口和输出采用不同位宽；当前 Google-30 复现也使用 8/16/32 位变量，并达到相对 FP32 小于 1 个百分点的 Top-1 差距。

现有 CNN 精度实验同样不能推出统一 32 位的必要性：统一 Q(16,s) 在若干模型上有明显损失，Q(24,s) 已接近 FP32，而只降低 ReLU 位宽时损失较小。统一低位宽失败可能来自范围、尺度、累加和截断语义，不能直接作为“宽位宽非线性输入必需”的证据。

需求必须回答三个问题：

1. 在相同混合位宽整数计算图上，分段 dealerless FSS 相对于 OT 后端是否降低离线、在线或通信成本？
2. 为满足预先固定的精度门槛，真正需要较宽位宽的是存储、乘积/累加器、比较输入，还是数学函数接口？
3. 32 位能力覆盖是否带来实际系统收益，还是只在强制统一高位宽的控制组中成立？

## Solution

以 SiRNN/SeeDot 原生 Google-30 FastGRNN 混合位宽图为主，建立可复现的协议对照链。第一阶段保留 SCI 的混合位宽线性层、扩环、截断和激活近似，只将相同功能的比较/MSB 原语替换为本项目的分段 FSS，形成明确命名的 `SCI + ours` 后端。先证明整数语义和最终预测一致，再测量协议成本。

比较采用双轨设计：

- **系统主表**允许各后端使用验证过的原生位宽优化，但必须满足相同质量门槛。
- **同数值图控制表**固定输入、权重、尺度、累加宽度、截断、舍入和激活近似，仅替换安全协议后端。

统一高位宽只作为受控实验。主要控制统一存储和算子 I/O 位宽，同时允许必要的宽乘积/累加；所有运算严格限制在同一环的版本只用于诊断，不能与前者混称为同一种 uniform 配置。

## Success Criteria

1. 对相同数值图，`SCI + ours` 的每个已替换算子输出与 SCI 的整数结果逐位一致；秘密份额本身不要求逐位相同，因为份额含随机性。
2. 在完整固定测试集上，`SCI + ours` 的整图定点预测与 SCI 基线完全一致。任何差异必须定位并修复后才能通过同图验收；给出解释或 Top-1 接近不能替代一致性。
3. 系统主表中所有可比较配置相对于同一 FP32 模型的 Top-1 损失不超过 1 个百分点，并同时报告与 FP32 的 prediction agreement。
4. 性能结果在相同机器、线程、batch、网络条件和重复次数下采集，分别报告 offline、online、total、通信量、轮数和峰值内存。
5. 密钥生成、乘法/截断预处理、扩环、位宽转换和私密输入转换均计入明确阶段成本；跨查询摊销必须标注摊销次数。
6. 宽度敏感性矩阵使用同一模型、权重、数据、激活近似和截断语义，至少包含 native mixed-width、统一存储/I-O 16 位和 32 位；必要时加入 64 位。结果报告 Top-1、agreement 和每类比较/FSS 输入宽度占比。
7. 按 Google-30 → ResNet-50/ImageNette → ResNet-152 顺序完成验证；后续架构以先前阶段的数值与安全接口为基础。

验收要求得到可信的比较结果，不预设 ours 必须获胜。精度未达标配置保留在完整结果中并标明未通过门槛，不进入达标配置的速度排名。

## User Stories

1. 作为论文作者，我希望把主张定义为“混合位宽图上的宽域 dealerless FSS 能力”，避免用统一 32 位必要性支撑证据不足的结论。
2. 作为论文作者，我希望分别记录存储/接口位宽、小数位、乘积宽度、累加器宽度、比较输入宽度和数学函数 I/O 宽度，从而解释精度和协议成本来源。
3. 作为实验设计者，我希望冻结官方 SeeDot Google-30 图的每个算子契约，避免协议后端比较同时改变数值算法。
4. 作为协议实现者，我希望保留 SCI 混合位宽线性路径并只替换比较/MSB 原语，从而先测出分段 FSS 的独立收益。
5. 作为协议实现者，我希望配置分段数并覆盖 16、20、24、32 位等比较输入，从而测量分段成本曲线。
6. 作为正确性验证者，我希望比较重构后的整数值而不是随机秘密份额，避免把合法分享随机性误判为协议错误。
7. 作为正确性验证者，我希望有逐算子和整图两级一致性检查，即使最终 Top-1 偶然相同时也能发现中间值错误。
8. 作为基准维护者，我希望主表包含 ours、同图 SCI/SiRNN OT 和 MP-SPDZ，从而比较相同威胁模型下的协议成本。
9. 作为基准维护者，我希望 ABY-64 和 dealer-assisted FSS 单列为 context，从而明确统一位宽或信任假设差异。
10. 作为精度实验者，我希望统一存储/I-O 控制允许宽乘积和累加，避免把禁止必要扩环导致的溢出误判为位宽不足。
11. 作为精度实验者，我希望严格同环版本单独标记为诊断，区分环回绕、尺度不足和存储量化造成的误差。
12. 作为实验分析者，我希望提前固定 Top-1 损失不超过 1 个百分点的门槛，避免看完性能结果后选择有利指标。
13. 作为实验分析者，我希望同时报告 Top-1 和 prediction agreement，区分净正确率变化与逐样本决策变化。
14. 作为系统评测者，我希望分别获得 offline、online、total、通信、轮数和峰值内存，判断收益来自密钥生成、在线轮次还是带宽。
15. 作为系统评测者，我希望在 LAN 和 WAN、相同线程和 batch 下重复测量，避免单次 localhost 结果代表端到端性能。
16. 作为复现者，我希望每个结果记录模型来源、权重版本、数据划分、量化配置、随机种子、命令和计量边界。
17. 作为论文作者，我希望把当前 30 条 SCI Google-30 结果描述为安全子集一致性证据，而不是完整测试集安全准确率。
18. 作为论文作者，我希望把当前 `structure_only` 的 CNN/RNN 行与安全端到端结果分开，避免把明文结构耗时写成安全推理性能。
19. 作为 CNN 扩展实施者，我希望先完成 ResNet-50/ImageNette，再扩展 ResNet-152，复用已有 Q(24,15) 与 ReLU16 精度证据。
20. 作为审稿人，我希望看到高位宽需求落在真实计算图的哪个算子和输入域，而不是只看到全局 `ell`。

## Implementation Decisions

### 数值契约

每个张量和算子必须记录：输入/输出总位宽、输入/输出尺度、乘积位宽、累加器位宽及累加长度、截断位置和舍入规则、溢出处理、比较/DPF/DCF/LUT 实际输入域宽、输出扩环/缩环和符号解释。

Google-30 原生图是第一主契约。当前复现的已知配置包括：输入和多数隐状态为 16 位，权重多数为 8 位，sigmoid 为 16 位输入/输出且尺度从 7 到 14，tanh 为 16 位输入/输出且尺度为 7 到 7；具体以生成程序和保存的量化产物为准，不能由容器类型推断。

### 后端结构

第一阶段实现 `SCI + ours`：

- SCI 保留原有混合位宽矩阵乘法、宽累加、扩环、截断和数学函数近似；
- 分段 FSS 替换相同功能的安全比较/MSB 原语；
- 位宽转换、输入掩码、密钥生成和跨段合并纳入计量；
- 当前 SIGMA 激活近似不直接当作 SiRNN 激活的逐位等价实现。

当前 SIGMA 安全激活接口只有一个共同的小数位参数，且其安全激活路径尚未使用分段计数。首期须用调用记录确认替换后的比较/MSB 确实进入分段 FSS；仅配置 `nseg` 或链接该库不算接入完成。

后续若独立替换整个激活函数，再提供独立输入/输出尺度和必要的安全转换、批处理。该工作改变数值近似，不是首期同图替换的前置条件。分段子域分解是协议实现，逐算子选择表示位宽是数值优化，两者分别记录。

### 比较矩阵

| 类别 | 配置 | 作用 |
|---|---|---|
| SCI + ours | SCI 数值路径与分段 FSS 比较/MSB | 首期目标后端 |
| 完整 ours | 全部所需安全算子接通后的后端 | 后续实现后才能单列实测结果 |
| SCI/SiRNN OT | 原生混合位宽图 | 同图纯 OT 对照 |
| MP-SPDZ | 匹配任务和数值契约的 semi2k/OT 配置 | 通用协议对照 |
| ABY-64 | 统一 64 位上下文结果 | 补充位宽上下文，不作为主排名 |
| dealer-assisted FSS | 含经销假设的历史结果 | 单独说明信任模型，不进入主表排名 |

每个 baseline 必须标出来源、威胁模型、数值图、位宽分配、可信经销者假设、离线/在线边界、可运行状态和缺失原因。

主比较采用一致的两方、无可信经销者、半诚实安全设置与安全参数；模型由服务方持有、输入由客户方持有，保持原生任务的输出揭示规则。ABY-64 也可以满足两方无经销假设，其单列原因是控制配置和比较定位，而非经销者依赖。MP-SPDZ 使用真实 OT 预处理，匹配的完整模型未接通时记录为不可用。

### 质量协议

- 质量门槛相对于同一 FP32 checkpoint 定义：Top-1 loss ≤ 1.0 percentage point；
- prediction agreement 作为独立指标，不替代 Top-1 门槛；
- 训练/校准集只用于选尺度或位宽，验证/测试集不得事后选点；
- 保留数据、权重、预处理、标签映射和测试样本顺序。

系统轨在同一浮点模型上允许后端分别量化，但候选选择规则和校准预算要记录并保持可比；同图轨则固定同一量化产物。定义 `loss_pp = FP32_Top1_pct - fixed_Top1_pct`，允许负值；agreement 不设置事后追加的准入阈值。0.5 pp 可作额外敏感性点，不改变已确认的 1.0 pp 主门槛。

### 宽度敏感性实验

使用同一 Google-30 模型和权重，至少运行：

1. native mixed-width；
2. uniform storage/I-O 16 位，允许必要的宽乘积/累加；
3. uniform storage/I-O 32 位，允许必要的宽乘积/累加；
4. 可选 uniform 64 位，前提是后端可复现且计量边界一致；
5. strict same-ring 版本作为诊断，不与主控制合并。

每行记录 Top-1、agreement、算子调用次数、比较/FSS 输入位宽占比、转换次数、累加器宽度和失败/溢出原因。

统一总位宽不要求所有张量使用同一小数位。位宽变化组保留数值规则与激活近似，按相同校准规则重新选择合法尺度；其量化产物可不同，不能称为逐位相同的计算图。同图轨在每个冻结配置内分别比较后端。

原语实验覆盖真实调用宽度，并补充 16/20/24/32 位及分段数 sweep。对可完成的单树配置给出实测对照；超时或内存不足记录资源上限，不作为完成时延。必要时比较直接宽域计算与“重定标/缩环＋窄域计算＋必要恢复”的总成本，两侧均允许合法融合和局部操作，不预设转换一定昂贵。

### 性能协议

所有可比较后端使用同一硬件、线程数、batch、输入顺序和网络条件。至少分别测量 LAN 与 WAN，并进行预先规定次数的重复运行。报告 offline/online/total latency、offline/online communication、dependent rounds、peak memory，以及密钥、三元组、掩码、扩环、截断和位宽转换的阶段分解。预处理跨查询摊销时，报告总查询数、摊销规则和未摊销首查询成本。

初始化/base OT、输入分享和输出重构均要有明确计量边界；提供包括初始化的首查询成本，以及可摊销初始化后的每查询成本。一次性 FSS 密钥、掩码和三元组每次推理重新消耗，不得通过重复使用降低成本。

通信以双方发送字节之和计链路总量，另存双方计数，避免将发送和接收重复累加。延迟记录双方数据并使用一致的端到端口径；内存记录各方峰值及报告口径。轮数区分协议依赖轮次与库 I/O 调用数；批量吞吐和单查询延迟分别报告。

### 执行阶段

#### P0：Google-30 契约冻结

输出完整算子契约、量化模型、测试清单、基线清单和可复现命令。任何未确认的位宽、尺度或舍入语义标为 blocker。

#### P1：SCI + ours 正确性闭环

完成逐算子整数输出比对、整图定点预测比对和异常定位。没有通过 P1，不得报告协议性能优于 SCI。

#### P2：Google-30 性能矩阵

在 native mixed-width 图上测量 `SCI + ours`、SCI/SiRNN OT 和 MP-SPDZ；补充分段数 sweep。主结果使用满足 Top-1 门槛的配置。宽度控制的精度验证完成后，再纳入相应配置的性能表。

#### P3：宽度敏感性分析

完成 native、uniform-16、uniform-32 和 strict-ring 诊断，统计实际宽域比较调用和转换成本；可与 P2 独立部分并行。该阶段决定论文是否可以在已评估任务、校准搜索和质量标准内声称宽域非线性输入有必要，不建立普遍最小位宽下界。

#### P4：CNN 扩展

先完成 ResNet-50/ImageNette 的安全后端和 Q(24,15)+ReLU16 对照；通过后再扩展 ResNet-152。已有明文宽累加结果不能替代安全后端结果。

CNN 使用已有 torchvision ImageNet-1K V1 权重、原始 1000 类输出头、512 张训练校准样本和完整 3,925 张 ImageNette 验证样本。报告数据范围，不将其称为完整 ImageNet 准确率。安全后端若改变宽累加、floor 缩放或饱和规则，应重新验证对应配置的精度。

### 实验产物与可配置项

各阶段交付算子契约与调用统计、校准候选及选点、逐样本预测、一致性报告、原始两方性能日志、统一结果 CSV/JSON 和复现命令。汇总表可以追溯到测量记录；模拟值与实测值分别标记。

线程数、batch、LAN/WAN 的 RTT/带宽、预热和重复次数、统计方法、分段数搜索范围、超时/内存预算在实施时配置并于正式测量前冻结。旧配置可作为起点，不自动代表本需求已确认的新设置。

文稿更新时，动机区分存储精度与实际 FSS 输入域；方法说明真实数值契约；实验分别呈现系统轨和同图轨。端到端、全测试集安全执行、性能优于基线等表述只对应已完成结果。

## Testing Decisions

### 正确性测试

- 在独立测试模式中，对固定输入和同一量化模型比较重构后的整数中间值；正式安全运行保持模型和输入原有保密规则，不开放中间值用于计时；
- 覆盖正负边界、零、最大/最小值、截断边界、段边界、符号扩展和溢出边界；
- 对每个比较域宽和分段数验证 DPF/DCF 输出；
- 对完整 Google-30 测试清单比较定点预测向量；
- 记录第一处差异的算子、张量、样本、位宽和尺度。

### 精度测试

- 使用同一 FP32 checkpoint 作为参考；
- 独立保存校准集和验证/测试集；
- 在看性能前冻结 Top-1 门槛；
- 同时输出 Top-1、FP32 agreement、基线 agreement、FP32 对/定点错和定点对/FP32 错；
- 不把明文宽临时累加器结果写成已验证的两方宽环结果。

### 性能测试

- 固定机器、编译选项、线程数、batch、连接条件和输入顺序；
- 分离首查询预处理、跨查询摊销和纯在线执行；
- 至少重复测量并报告中心趋势和离散程度；
- 对 LAN/WAN 分别记录离线、在线、总延迟、通信、轮数和峰值内存；
- 未实现的安全 executor 输出 `unavailable`，不得用 smoke、structure-only 或明文耗时填充安全列。

### 回归测试

- 复用受本次改动影响的 DPF/DCF、截断、BitXA 等已有测试，在算子接口和整图输出处验证行为，不重复构建只检查实现细节的测试；
- 新增 mixed-width 转换后验证符号扩展、缩环和尺度转换的整数语义；检查共享接口与允许打开的值，安全性依据协议论证，不能由数值测试通过代替；
- 任何激活近似替换必须有独立 ULP/任务精度结果，不能混入同数值图后端对照。

## Out of Scope

- 不主张所有 CNN/RNN 普遍需要统一 32 位或 64 位。
- 不把统一 32 位控制结果当作 SiRNN 原生 mixed-width baseline。
- 不把 dealer-assisted FSS 与 dealerless 两方协议放入同一性能排名。
- 不把当前 structure-only 或明文 fixed-point runtime 描述为安全端到端性能。
- 不把 30 条 Google-30 SCI 子集描述为完整测试集安全准确率。
- 不在第一阶段同时重写全部 CNN、FastGRNN、LSTM 和激活后端。
- 不用事后挑选验证集尺度、agreement 或 Top-1 指标来满足质量门槛。
- 不把宿主机 128 位临时整数容器等同于已实现的两方 128 位秘密共享协议。
- 不把改变数学函数近似和替换安全比较协议的结果放在同一“同数值图”对照中。

## Further Notes

### 当前已知证据

- Google-30 FP32 test 为 90.3731%，SeeDot mixed-width 为 89.7440%，差 0.6291 个百分点；当前 SCI 两方验证了 30 条样本与 SeeDot 预测一致。
- ImageNette 的宽累加统一 Q(24,15) 结果已接近 FP32；全网统一 Q(16,s) 在部分 ResNet 上明显退化；仅 ReLU 使用 Q(16,s) 的退化较小。
- 这些结果支持“位宽、尺度和算术语义需要共同设计”，不支持“32 位是普遍最小精度”。
- 上述 Google-30 数字是 2026-10-07 的历史复现锚点：该复现的 checkpoint 依据压缩阶段 test accuracy 选择，量化 fixer 还使用了完整 train/test 范围；它可用于冻结协议图和做一致性对照，但不能被标为严格独立的最终质量结果。正式质量结果必须使用独立于模型/量化选择的评估产物，并单独记录其选择流程。

### 论文措辞边界

论文拟验证的是分段 dealerless FSS 在原生混合位宽图中的贡献，而非新的混合精度量化算法。根据实测结果确定结论范围：

- 原生混合位宽下有收益：支持该图与实验条件下的推理加速结论。
- 收益集中于宽域：报告达标配置中的宽域调用比例、成本占比和转换代价。
- 仅人为统一高位宽后有收益：限定为该配置下的协议优势，不推广为通用推理加速。

只有当 P3 在允许逐算子尺度和合法扩宽的比较中仍发现宽域需求时，才增加任务范围内的必要性论证；否则 32 位是能力覆盖点。实验完成不以获得有利结论为条件。
